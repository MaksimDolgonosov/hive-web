# Hive — ТЗ: публичный сайт hive-app.site

Версия: 0.1
Назначение: закрыть требования Google Play и Apple к публичным URL и дать приложению лицо в браузере.
Стек: React 19 + TypeScript + Vite, react-router, i18next. Статическая сборка, без сервера приложений и без базы.
Домен: `https://hive-app.site` (регистратор hoster.by, DNS в расширенном редакторе).
Смежные документы: `legal/privacy-policy.ts`, `legal/community-guidelines.ts`, `google_therms.md`, `RN_FRONTEND_TZ.md` §10.

Сайт не является частью продукта Hive. Это юридическая и маркетинговая витрина. Аккаунтов, входа, API и запросов к бэкенду на нём нет.

## 1. Зачем это нужно

Google Play не принимает политику конфиденциальности, которая живёт только внутри приложения, и требует отдельный публичный адрес, где удаление аккаунта можно запросить **без приложения**. Оба поля в Play Console принимают только `https://`-ссылку: ни текст, ни адрес почты туда не вставляются.

Из этого следуют две обязательные страницы: политика и удаление аккаунта. Правила сообщества и описание продукта обязательными не являются, но без них сайт выглядит как заглушка, а ревьюер хуже верит, что приложение реальное.

Кнопка «Удалить аккаунт» внутри Hive (Профиль → Настройки) уже есть. Сайт её **не заменяет**: Google требует оба пути одновременно.

## 2. Инварианты — что нельзя ломать

| # | Инвариант | Следствие |
| --- | --- | --- |
| W1 | Только HTTPS | Открытый `http://` Play отклоняет. Редирект `http → https` обязателен |
| W2 | Страницы открываются без входа и без приложения | Ни логина, ни капчи, ни модалки «скачайте приложение» перед контентом |
| W3 | `/delete-account` — прямой адрес, а не раздел главной | В консоль идёт URL самой страницы, не `https://hive-app.site` с ссылкой где-то внизу |
| W4 | На каждой странице видно имя **Hive** | Так, как оно стоит в карточке Play. Без этого ссылку могут не принять |
| W5 | Текст политики и правил совпадает с текстом в приложении | Источник один (§5). Расхождение раскрытия данных — причина отказа |
| W6 | DNS: MX и TXT-записи не трогаем | Домен уже отдан на приём почты и отправку писем. Сайт добавляет только A/CNAME |
| W7 | Нет аналитики, рекламы и трекеров | Иначе придётся раскрывать сбор данных сайтом, а в анкете Data safety заявлено «без рекламы» |
| W8 | Ссылки на сторы не ведут в никуда | Пока приложения нет в сторах — заглушки на главные страницы App Store и Google Play, не пустой `href` и не 404 |

Нарушение W1–W4 делает сайт бесполезным: Play его не зачтёт, а работа будет выглядеть сделанной.

## 3. Карта страниц и маршруты

| Маршрут | Страница | Обязательна для стора |
| --- | --- | --- |
| `/` | Главная: о приложении, ссылки на сторы | Нет |
| `/privacy` | Политика конфиденциальности | Да |
| `/community-guidelines` | Правила сообщества | Нет |
| `/delete-account` | Удаление аккаунта и данных | Да |
| `/ru`, `/ru/privacy`, `/ru/community-guidelines`, `/ru/delete-account` | То же на русском | Нет |
| `*` | 404 с ссылкой на главную | Нет |

Маршрутизация — `react-router` в режиме `BrowserRouter`. Сборка статическая, поэтому на хостинге нужен fallback всех неизвестных путей на `index.html`, иначе прямой переход на `/delete-account` отдаст 404 сервера, и ссылка в консоли будет считаться нерабочей (W1, W3).

## 4. Языки

Язык по умолчанию — **английский**. Русский — второй.

- Английские страницы живут на путях без префикса: `/privacy`, `/delete-account`. Именно эти адреса идут в Play Console.
- Русские — с префиксом `/ru`. Отдельного `/en` нет, чтобы у каждой страницы был один канонический адрес.
- Переключатель языка в хедере, две ссылки `EN` и `RU`, сохраняет текущую страницу: с `/ru/privacy` ведёт на `/privacy`.
- Выбор языка запоминается в `localStorage`. Автоопределение по `navigator.language` допускается **только на первом заходе на `/`** и не должно делать редирект с `/delete-account`: ревьюер должен увидеть ту страницу, адрес которой он открыл.
- Атрибут `<html lang>` переключается вместе с языком. На каждой странице `<link rel="alternate" hreflang>` на обе версии.

Переводы интерфейса (меню, подписи кнопок, футер) — `i18next` с двумя файлами `src/i18n/en.ts` и `src/i18n/ru.ts`. Юридические тексты через i18next **не** идут: у них отдельный источник (§5).

## 5. Источник юридических текстов

В приложении политика и правила лежат не как HTML, а как данные: массив секций с заголовками и блоками `paragraph` / `list`. Типы — `legal/document.ts` в `hive-app`:

```ts
export type LegalBlock = { type: 'paragraph'; text: string } | { type: 'list'; items: string[] };
export type LegalSection = { heading: string; blocks: LegalBlock[] };
export type LegalDocument = { title: string; intro: string; sections: LegalSection[] };
```

Сайт переиспользует эти же данные:

1. Файлы `legal/document.ts`, `legal/privacy-policy.ts`, `legal/community-guidelines.ts` копируются в веб-проект в `src/legal/` без правок текста. В импортах меняется только алиас `@/legal/...` на относительный путь.
2. Один компонент `LegalDocumentView` рендерит `LegalDocument`: `title` в `<h1>`, `intro` абзацем, каждую секцию в `<h2>` плюс `<p>` и `<ul>`.
3. Язык документа берётся из текущего языка сайта: `getPrivacyPolicyDocument(lang)` и `getCommunityGuidelinesDocument(lang)` уже принимают строку языка.

Так текст на сайте совпадает с тем, что человек принимает галочкой при регистрации (W5). Markdown-копии `legal/privacy-policy.ru.md` и `legal/privacy-policy.en.md` как источник не использовать: они вторичны и могут отстать.

**Расхождение, которое нужно решить до публикации.** В политике и правилах контакт — `privacy@hive.app`. Этот домен принадлежит другой компании, ящик там не заведён. На странице удаления по этому ТЗ указан `hive.app.site@gmail.com`. Пока адреса разные, ревьюер видит в политике один контакт, а на странице удаления другой. Правильный порядок: завести рабочий ящик, затем сменить `PRIVACY_CONTACT_EMAIL` в `hive-app/legal/privacy-policy.ts` и `REPORT_EMAIL` в `hive-backend-nodejs/src/services/safety-reports.service.ts`, затем скопировать обновлённые файлы на сайт. Это за пределами веб-проекта, но без этого шага W5 не выполняется.

## 6. Главная страница

Цель: за один экран объяснить, что такое Hive, и дать две кнопки сторов.

Блоки сверху вниз:

1. **Хедер.** Знак Hive и слово HIVE, переключатель языка. Знак — тот же градиентный ромб, что в приложении (`src/components/auth/AuthLogo.tsx`), или PNG-иконка из `assets/Hive.icon`.
2. **Герой.** Заголовок и строка-слоган. Слоган брать из приложения: en `A social map of moments`, ru `Социальная карта моментов`. Ниже абзац: Hive — карта моментов, фото снимаются встроенной камерой на месте, живут от 4 до 72 часов и исчезают; там, где снимков много, появляется улей.
3. **Кнопки сторов.** App Store и Google Play, по правилам §8 ниже.
4. **Как это работает.** Три короткие карточки: снимок только с камеры в точке, где вы стоите; момент живёт от 4 до 72 часов; скопление моментов превращается в улей. Текст не выдумывать — брать смысл из онбординга (`src/i18n/locales/en.ts`, раздел `onboarding`).
5. **Приватность одним абзацем.** Геолокация нужна для карты и привязки снимка к месту; точные координаты опубликованного фото видят другие пользователи, пока фото активно. Фраза должна совпадать по смыслу с экраном онбординга и политикой.
6. **Футер.** Ссылки: Privacy Policy, Community Guidelines, Delete account, контактный email. Строка «Hive — a social map of moments» и год.

Ссылка на `/delete-account` в футере обязательна на всех страницах: Google требует, чтобы путь к удалению был легко обнаружим.

### Кнопки сторов

Бейджи — официальные картинки «Download on the App Store» и «Get it on Google Play» (`public/illustrations/`). Когда появятся карточки Hive, правится только `stores.ts`, вёрстка не меняется.

Конфиг `src/config/stores.ts`. Пока приложения нет в сторах, значения — заглушки, не `null` и не адрес карточки Hive (W8):

```ts
export const STORE_LINKS = {
  appStore: 'https://apps.apple.com/',
  googlePlay: 'https://play.google.com/store',
};
```

`href="#"`, `href=""` и ссылки на несуществующие страницы стора запрещены.

Клик зависит от устройства:

- **Телефон** (`iPhone`, `iPod`, `Android` с `Mobile` в user agent). Обычный переход по `href` сразу в App Store или Google Play. Модальное окно не показывается.
- **Компьютер** (всё остальное, включая планшет). Переход отменяется. По центру экрана плавно появляется модальное окно, задний фон затемняется. В окне QR-код, в котором закодирована та же ссылка из `stores.ts`: человек сканирует его телефоном и попадает в стор. Закрытие — по затемнению, по кнопке и по Escape.
- QR собирается в браузере из URL. Запрос к внешнему генератору кодов запрещён (W7).
- Окно не показывается само при загрузке страницы и не перекрывает контент до клика (W2).

## 7. Страница удаления аккаунта

Самая важная страница. Адрес ровно `https://hive-app.site/delete-account`, он же идёт в Play Console.

Требования Google к этой странице, которые вёрстка обязана выполнить:

- открывается без ошибки и без входа;
- путь к удалению виден сразу, без прокрутки на мобильном;
- на странице есть имя приложения — **Hive**;
- человек может подать запрос, не возвращаясь в приложение и не устанавливая его заново;
- сказано, что удаляется и что может быть сохранено.

Структура:

1. `<h1>` с названием: `Delete your Hive account` / `Удаление аккаунта Hive`.
2. Короткое вступление: на этой странице можно удалить аккаунт Hive или запросить удаление, если приложения на устройстве больше нет.
3. **Способ 1 — в приложении.** Явные шаги: `Profile → Settings → Delete account` / `Профиль → Настройки → Удалить аккаунт`. Оформить как нумерованный список, не одним абзацем.
4. **Способ 2 — без приложения.** Написать письмо на `hive.app.site@gmail.com` с того адреса электронной почты, к которому привязан аккаунт. Email оформить как `mailto:`-ссылку с готовой темой, например `?subject=Delete%20my%20Hive%20account`. Отдельной строкой: письмо должно прийти именно с почты аккаунта, иначе владельца невозможно подтвердить.
5. **Что удаляется.** Список: профиль, фото, сессии. Дополнительно, чтобы список совпадал с политикой: лайки и реакции.
6. **Что может сохраниться.** Отдельный абзац: часть данных может храниться дольше, если это требуется по закону или для защиты от злоупотреблений. Этого требует Google: простое «отключение» аккаунта удалением не считается, а удержание данных нужно раскрывать.
7. **Срок.** Сколько идёт обработка письма. Значение нужно подтвердить; по умолчанию в ТЗ — 30 дней.
8. Ссылка на `/privacy`.

Формы с полями и отправкой на сервер на странице нет: `mailto:` достаточно, Google прямо допускает запрос через почту поддержки. Это сознательно удерживает сайт статическим.

## 8. Политика и правила сообщества

- `/privacy` и `/ru/privacy` рендерят `getPrivacyPolicyDocument(lang)`.
- `/community-guidelines` и `/ru/community-guidelines` рендерят `getCommunityGuidelinesDocument(lang)`.
- Обе страницы — один компонент `LegalPage`, отличается только документ.
- Длинный текст: ограничить ширину колонки примерно 70 символами, межстрочный интервал не меньше 1.6.
- На `/privacy` раздел про удаление данных должен быть заметен: добавить в начало страницы ссылку-анкор на этот раздел и ссылку на `/delete-account`. Google разрешает закрывать требование существующей политикой, только если раздел удаления выделен и доступен по анкору.
- Оглавление по секциям — опционально, но на мобильном помогает.

## 9. Дизайн и адаптивность

Сайт должен выглядеть как то же приложение. Токены брать из `src/theme/tokens.ts`:

| Роль | Светлая тема | Тёмная тема |
| --- | --- | --- |
| Фон | `#FFF8ED` | `#0B0A08` |
| Текст | `#2C1810` | `#F6F2EA` |
| Текст второго плана | `#8B7355` | `#9C9287` |
| Акцент | `#B99A55` | `#B99A55` |
| Градиент знака | `#FFD54F → #F5A623 → #FF8C00` | `#241E14 → #13110C → #0A0907` |

- Базовая тема светлая. Тёмную поддержать через `prefers-color-scheme`, переключателя темы не делать.
- Мобильная вёрстка обязательна: большинство откроет ссылку с телефона. Проверять на ширине 360 CSS-пикселей.
- Шрифты системные (`system-ui`), без подключения Google Fonts: внешний запрос шрифтов — это передача IP-адреса третьей стороне, что пришлось бы раскрывать (W7).
- Стилизация — CSS-модули или один глобальный CSS-файл с переменными. Tailwind допустим, но не обязателен: страниц мало.
- Доступность: контраст не ниже AA, видимый фокус, осмысленный `alt` у картинок, один `<h1>` на страницу.

## 10. Структура проекта

Отдельный репозиторий, например `hive-web`. В `hive-app` его не вкладывать: у них разные сборки и разные зависимости.

```
hive-web/
  index.html
  package.json
  tsconfig.json

  public/
    favicon.png

  src/
    main.tsx
    App.tsx
    config/stores.ts
    i18n/{index.ts,en.ts,ru.ts}
    legal/{document.ts,privacy-policy.ts,community-guidelines.ts}
```

Зависимости: `react`, `react-dom`, `react-router-dom`, `i18next`, `react-i18next`. Больше ничего не нужно. Dev: `typescript`, `vite`, `@vitejs/plugin-react`, `eslint`, `prettier`.

`tsconfig` в strict-режиме. Скрипты: `dev`, `build`, `preview`, `lint`, `typecheck`.

## 11. SEO, метатеги, индексация

- `<title>` и `<meta name="description">` своё на каждой странице и на каждом языке. Компонент `Seo` пишет их в `document.head` при монтировании.
- Open Graph: `og:title`, `og:description`, `og:image` (1200×630, можно иконку приложения на фирменном фоне), `og:url`, `og:type=website`.
- `<link rel="canonical">` на адрес без префикса для английской версии и на `/ru/...` для русской.
- `robots.txt` разрешает индексацию всего и указывает `Sitemap`.
- `sitemap.xml` со всеми восемью адресами из §3.
- Страницы должны быть читаемы без JavaScript хотя бы в виде заголовка и ссылки на email. Если это неудобно, допустимо оставить SPA, но в `index.html` положить `<noscript>` с текстом: как удалить аккаунт и на какой адрес писать. Ревьюер может открыть страницу в окружении без скриптов.

## 12. Хостинг, DNS, HTTPS

- Сборка статическая (`vite build` → `dist`). Подойдёт любой статический хостинг с бесплатным TLS. Хостинг у hoster.by тоже годится.
- Обязательны: сертификат TLS, редирект `http → https`, редирект `www → без www` или наоборот (один канонический вариант).
- Fallback на `index.html` для всех путей, иначе прямой вход на `/delete-account` вернёт 404 сервера (W3).
- DNS в расширенном редакторе hoster.by: добавить только `A` для `hive-app.site` и `CNAME` для `www`, либо записи, которые требует выбранный хостинг.
- Записи `MX` (`aspmx.l.google.com`, `alt1`–`alt4`), `TXT` (`v=spf1`, `_dmarc`, `resend._domainkey`) и `CNAME` `send`, `rsend`, `mail` **не менять и не удалять** (W6). Через них работают приём почты и отправка писем с кодом из приложения.

## 15. Риски

| Риск | Проявление | Что делать |
| --- | --- | --- |
| Разные контакты в политике и на странице удаления | Ревьюер видит `privacy@hive.app` в политике и Gmail на сайте | Свести к одному адресу до заявки (§5) |
| `hive.app.site@gmail.com` не существует или не читается | Письма на запрос удаления уходят в пустоту, при проверке это выяснится | Проверить ящик вручную (W8) и назначить, кто его читает |
| Публичный Gmail на статической странице | Спам на адрес | Допустимо на старте. Позже — ящик на своём домене или веб-форма |
| Нет SPA-fallback на хостинге | Прямой вход на `/delete-account` даёт 404, Google считает ссылку нерабочей | Проверять именно прямым переходом, не кликом из меню |
| Автоопределение языка с редиректом | Открытый `/delete-account` уводит на `/ru/delete-account`, адрес из консоли «не тот» | Автоопределение только на `/` |
| Ссылки в приложении ведут на `hive.app` | Приглашения и карточки мест открывают чужой сайт | Отдельная задача: перенести `https://hive.app/i/...` и `/p/...` на новый домен. В этом ТЗ не делается |
| Домен `hive-app.site` и слово Hive в сторе | Домен не совпадает с названием | Для Play достаточно, чтобы имя Hive было на самих страницах (W4) |

## 16. Приёмочный чек-лист

- [ ] `https://hive-app.site/delete-account` открывается прямым вводом адреса в новом окне браузера, без входа
- [ ] На этой странице в первом экране мобильного видно слово Hive, шаги Профиль → Настройки → Удалить аккаунт и адрес для письма
- [ ] `mailto:`-ссылка открывает письмо с заполненной темой
- [ ] Написано, что удаляются профиль, фото и сессии, и что часть данных может сохраняться по закону
- [ ] `https://hive-app.site/privacy` открывается и текст совпадает с экраном политики в приложении
- [ ] Правила сообщества открываются и совпадают с экраном правил в приложении
- [ ] Язык по умолчанию английский; `/ru/...` даёт русский; переключатель сохраняет страницу
- [ ] `http://hive-app.site` редиректит на `https://`
- [ ] Ни одна ссылка на страницах не ведёт на 404 и не является пустой; бейджи сторов ведут на заглушки, с компьютера открывают QR, с телефона — сам стор
- [ ] Страницы читаются на ширине 360 px
- [ ] В DNS по-прежнему на месте записи MX, SPF, DMARC, DKIM и CNAME `send`, `rsend`, `mail`
- [ ] Письмо на `hive.app.site@gmail.com` доходит
- [ ] Оба URL приняты в Play Console без замечаний

## 17. Вне скоупа

- Вход на сайте, веб-версия карты, просмотр фото в браузере.
- Веб-форма удаления с запросом к бэкенду и само удаление по кнопке на сайте: внутри приложения это уже есть, снаружи достаточно письма.
- Публичные OG-страницы приглашений `/i/{code}` и мест `/p/{id}`: сейчас они живут на `hive.app` и требуют отдельного решения.
- Блог, цены, поддержка, формы обратной связи.
- Аналитика, cookie-баннер, согласие на cookie: трекеров нет, баннер не нужен.
